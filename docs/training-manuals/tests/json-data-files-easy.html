JSON Data Files

Data-Driven Testing — Training Manual

Parameterize your API tests with JSON data files — import test data as simple arrays or structured templates with metadata, path variables, query parameters, and validation rules.

RedfireForge v0.8.0

1. What Are JSON Data Files?

JSON Data Files let you run the same API test with many different inputs — different IDs, query parameters, request bodies, and expected values — without manually creating each test case. Each object in the JSON file becomes a separate test scenario when imported.

This is the same data-driven testing concept as CSV/Excel templates, but using JSON format — ideal when:

  • Your test data already exists as JSON (API responses, seed scripts, CI fixtures).
  • Values contain nested objects or arrays that CSV can't represent cleanly.
  • You prefer JSON over spreadsheets for managing test parameters.
  • You want to version-control test data alongside code in git.
💡 CSV vs JSON — When to Use Which Use CSV/Excel when your QA team works in spreadsheets, or when you need the 3-step export wizard with styled headers and column customization. Use JSON when your data is already in JSON format, when values contain nested structures, or when you want simple copy-paste-edit workflows.

2. Two Supported Formats

RedfireForge accepts two JSON formats. Both produce the same result — each object becomes one test scenario.

Format A — Simple Array

A plain JSON array of objects. Each object must have name and url. Optional: method (defaults to GET), body.

[
  {
    "name": "Get all users",
    "url": "https://jsonplaceholder.typicode.com/users",
    "method": "GET"
  },
  {
    "name": "Create a post",
    "url": "https://jsonplaceholder.typicode.com/posts",
    "method": "POST",
    "body": "{\"title\": \"Hello\", \"userId\": 1}"
  }
]

Best for: Quick imports from existing JSON data. No metadata needed — each test is self-contained.

Format B — Structured with Metadata

An object with meta (test template settings) and data (array of rows). Rows use prefixed keys: path:, param:, validate:.

{
  "meta": {
    "version": 1,
    "method": "GET",
    "urlPattern": "https://dummyjson.com/products/{{productId}}",
    "headers": [{ "key": "Accept", "value": "application/json" }],
    "body": "",
    "auth": { "type": "none" },
    "validationMode": "selective",
    "selectiveMode": "include",
    "pathVariables": ["productId"]
  },
  "data": [
    {
      "name": "Product 1 — verify category",
      "path:productId": "1",
      "validate:$.category": "beauty"
    },
    {
      "name": "Product 6 — verify category",
      "path:productId": "6",
      "validate:$.category": "fragrances"
    }
  ]
}

Best for: Export → edit → reimport workflows. Metadata carries the method, URL pattern, headers, auth, and validation settings shared across all rows.

3. Key Prefixes (Structured Format)

In the structured format, data row keys use prefixes to tell RedfireForge what each value represents:

Prefix Purpose Example Key Example Value
path: Path variable — substituted into {{placeholders}} in the URL pattern path:vin 3FAHP0HA8CR123456
param: Query parameter — appended as ?key=value param:channel WEB
validate: Expected field — JSONPath and expected value for selective validation validate:$.data.status active
name Test name (required, no prefix) name US VIN lookup
📋 Note These are the same prefixes used by CSV templates. If you're familiar with CSV data files, structured JSON works identically — just in JSON syntax.

4. Metadata Fields Reference

The meta object in the structured format contains these fields:

Field Type Description
versionnumberSchema version (always 1)
methodstringHTTP method: GET, POST, PUT, DELETE, PATCH
urlPatternstringURL with {{placeholders}} for path variables
headersarrayRequest headers as [{ "key": "...", "value": "..." }]
bodystringRequest body (shared across all rows)
authobjectAuth config: { "type": "none" }, "basic", "bearer", "oauth2", etc.
validationModestring"none", "full", or "selective"
selectiveModestring"include" or "exclude" (for selective validation)
pathVariablesarrayList of variable names used in urlPattern

5. How to Import JSON Data Files

Step 1 — Open the Import Modal

  1. Navigate to the Harness section in the left sidebar.
  2. Click the Import Template button in the toolbar.

Step 2 — Upload Your JSON File

  1. Drag and drop a .json file onto the drop zone, or click to browse.
  2. The modal will parse the file and show a preview: total rows, valid rows, error rows.

Step 3 — Choose Destination

  1. Select an existing Feature Group and Scenario to import into, or create new ones.
  2. Click Import N Tests to create one test scenario per JSON row.
💡 Tip The import preview shows row-level validation errors. Rows with missing name or url (for simple arrays) or missing path variables (for structured format) are flagged in red — fix them in your JSON file and re-upload.

6. How to Export a JSON Template

You can generate a structured JSON template from any existing test:

  1. Open the Test Editor for any test scenario.
  2. Click Export Template.
  3. Select path variables (URL segments that change per row).
  4. The exported JSON file contains one sample row pre-filled with the test's current values, plus metadata for method, headers, auth, and validation rules.
  5. Open the downloaded .json file, duplicate the sample row, and fill in your test data.
  6. Re-import the file to create all test cases at once.

7. Error Handling

The parser validates each row and reports errors in the import preview:

ErrorCauseFix
Invalid JSON File is not valid JSON Check syntax — use a JSON validator
Missing name Row object has no name field or it's empty Add a "name" field to every row
Missing url Simple array row has no url field (and no metadata) Add "url" to the row, or use structured format with meta.urlPattern
Missing path variable: X Structured format: row is missing a required path:X value Add the "path:X" field with a non-empty value
Row is not an object Simple array contains a non-object element (string, number) Ensure every array element is a { ... } object

8. Examples

Example 1 — Quick Smoke Tests (Simple Array)

File: examples/json-data-simple.json

[
  { "name": "Get all users", "url": "https://jsonplaceholder.typicode.com/users" },
  { "name": "Get user by ID", "url": "https://jsonplaceholder.typicode.com/users/1" },
  { "name": "Create post", "url": "https://jsonplaceholder.typicode.com/posts",
    "method": "POST", "body": "{\"title\": \"Hello\", \"userId\": 1}" },
  { "name": "Get posts for user 2", "url": "https://jsonplaceholder.typicode.com/posts?userId=2" }
]

Each object imports as a standalone test. No shared settings — each row defines its own URL and method.

Example 2 — Product Lookup with Validation (Structured)

File: examples/json-data-structured.json

{
  "meta": {
    "version": 1,
    "method": "GET",
    "urlPattern": "https://dummyjson.com/products/{{productId}}",
    "headers": [{ "key": "Accept", "value": "application/json" }],
    "auth": { "type": "none" },
    "validationMode": "selective",
    "pathVariables": ["productId"]
  },
  "data": [
    { "name": "Product 1", "path:productId": "1", "validate:$.category": "beauty" },
    { "name": "Product 6", "path:productId": "6", "validate:$.category": "fragrances" },
    { "name": "Product 10", "path:productId": "10", "validate:$.category": "fragrances" }
  ]
}

All rows share the same method, URL pattern, headers, and auth. Each row provides a different productId and expected category value.

9. Step-by-Step Walkthrough

Follow these two end-to-end walkthroughs using the sample files included with RedfireForge.

Walkthrough A — Simple Array (examples/json-data-simple.json)

This sample contains 4 JSONPlaceholder API tests as a flat array — no metadata, no shared settings.

Step 1 — Prepare the Sample File

Copy the JSON below and save it as json-data-simple.json on your computer:

[
  {
    "name": "Get all users",
    "url": "https://jsonplaceholder.typicode.com/users",
    "method": "GET"
  },
  {
    "name": "Get user by ID",
    "url": "https://jsonplaceholder.typicode.com/users/1",
    "method": "GET"
  },
  {
    "name": "Create new post",
    "url": "https://jsonplaceholder.typicode.com/posts",
    "method": "POST",
    "body": "{\"title\": \"Hello World\", \"body\": \"This is a test post\", \"userId\": 1}"
  },
  {
    "name": "Get posts for user 2",
    "url": "https://jsonplaceholder.typicode.com/posts?userId=2",
    "method": "GET"
  }
]

Step 2 — Open the Import Modal

  1. In the left sidebar, click Harness to open the Test Harness view.
  2. Click the Import Template button in the toolbar (or use the ⌘+I shortcut).
  3. The import modal opens showing Step 1 — Choose a file.

Step 3 — Upload the File

  1. Click Browse Files (or drag the file into the drop zone).
  2. Select the json-data-simple.json file you saved in Step 1.
  3. The modal advances to Step 2 — Preview.

Step 4 — Review the Preview

  1. You should see a table with 4 rows:
    • Get all users — GET https://jsonplaceholder.typicode.com/users
    • Get user by ID — GET https://jsonplaceholder.typicode.com/users/1
    • Create post — POST https://jsonplaceholder.typicode.com/posts
    • Get posts for user 2 — GET https://jsonplaceholder.typicode.com/posts?userId=2
  2. The Valid column shows ✅ for all 4 rows (each has a name and url).
  3. Notice row 3 ("Create post") has method: POST and a JSON body — these were parsed from the file.

Step 5 — Choose a Destination

  1. Under Target Feature Group, select Create New.
  2. Enter the name: JSON Import — Simple.

Step 6 — Import

  1. Click the Import button.
  2. The modal closes and the sidebar now shows the new feature group JSON Import — Simple with 4 test scenarios inside.

Step 7 — Run and Verify

  1. Click the Run All button on the feature group.
  2. All 4 tests execute against the live JSONPlaceholder API.
  3. Expected results:
    • "Get all users" → 200 OK, response is an array of 10 user objects.
    • "Get user by ID" → 200 OK, response contains "id": 1.
    • "Create post" → 201 Created, response contains "id": 101.
    • "Get posts for user 2" → 200 OK, response is an array of posts.
  4. All tests should show a green ✅ pass status.
💡 Tip Click any test row to expand the response detail panel and inspect the full JSON response body, headers, and timing.

Walkthrough B — Structured Format (examples/json-data-structured.json)

This sample uses the structured format with metadata, path variables, and selective validation — 5 DummyJSON product lookups.

Step 1 — Prepare the Sample File

Copy the JSON below and save it as json-data-structured.json on your computer:

{
  "meta": {
    "version": 1,
    "method": "GET",
    "urlPattern": "https://dummyjson.com/products/{{productId}}",
    "headers": [
      { "key": "Accept", "value": "application/json" }
    ],
    "body": "",
    "auth": { "type": "none" },
    "validationMode": "selective",
    "selectiveMode": "include",
    "pathVariables": ["productId"]
  },
  "data": [
    {
      "name": "iPhone — verify title and price",
      "path:productId": "1",
      "validate:$.title": "Essence Mascara Lash Princess",
      "validate:$.category": "beauty"
    },
    {
      "name": "Calvin Klein CK One — verify category",
      "path:productId": "6",
      "validate:$.category": "fragrances"
    },
    {
      "name": "Product 10 — basic check",
      "path:productId": "10",
      "validate:$.category": "fragrances"
    },
    {
      "name": "Product 15 — exists",
      "path:productId": "15"
    },
    {
      "name": "Product 20 — exists",
      "path:productId": "20"
    }
  ]
}

Step 2 — Open the Import Modal

  1. Click Import Template in the Harness toolbar again.

Step 3 — Upload the File

  1. Click Browse Files and select the json-data-structured.json file you saved in Step 1.
  2. The modal advances to the preview step.

Step 4 — Review the Preview

  1. You should see a table with 5 rows:
    • iPhone — verify title and price — GET https://dummyjson.com/products/1
    • Calvin Klein CK One — verify category — GET https://dummyjson.com/products/6
    • Product 10 — basic check — GET https://dummyjson.com/products/10
    • Product 15 — exists — GET https://dummyjson.com/products/15
    • Product 20 — exists — GET https://dummyjson.com/products/20
  2. Notice how the URL pattern https://dummyjson.com/products/{{productId}} from meta.urlPattern was resolved — each row's path:productId value replaced the {{productId}} placeholder.
  3. The Validation column shows that the first 3 rows have selective assertions (e.g., $.category = "beauty"), while rows 4–5 have no validation (just checking the endpoint responds).

Step 5 — Choose a Destination

  1. Select Create New and name it: JSON Import — Products.

Step 6 — Import

  1. Click Import.
  2. The feature group JSON Import — Products appears with 5 test scenarios.

Step 7 — Inspect the Imported Tests

  1. Click on iPhone — verify title and price to open it in the Test Editor.
  2. Verify the following were applied from metadata:
    • Method: GET
    • URL: https://dummyjson.com/products/1 (path variable resolved)
    • Headers: Accept: application/json (from meta.headers)
    • Validation: Selective mode with assertions $.title = "Essence Mascara Lash Princess" and $.category = "beauty"
  3. Click on Calvin Klein CK One — verify category — same structure but URL ends in /6 and expected category is "fragrances".

Step 8 — Run and Verify Assertions

  1. Click Run All on the feature group.
  2. All 5 tests execute against the live DummyJSON API.
  3. Expected results:
    • iPhone — verify title and price → 200 OK, $.category = "beauty" ✅
    • Calvin Klein CK One — verify category → 200 OK, $.category = "fragrances" ✅
    • Product 10 — basic check → 200 OK, $.category = "fragrances" ✅
    • Product 15 — exists → 200 OK (no validation, just connectivity) ✅
    • Product 20 — exists → 200 OK (no validation, just connectivity) ✅
  4. If any assertion fails, click the test to see the Assertion Details panel showing expected vs actual values.
💡 Key Takeaway The structured format is powerful for parameterized testing — you define shared settings once in meta, then each data row only needs its unique values. This keeps your test data DRY and easy to maintain.

10. Additional Exercises

Exercise 1 — Create Your Own Simple JSON

  1. Pick any public API you've used (e.g., PokéAPI, REST Countries).
  2. Create a new .json file with 3–5 test cases as a simple array.
  3. Import it into RedfireForge and run all tests.

Exercise 2 — Convert Simple to Structured

  1. Take your simple JSON from Exercise 1.
  2. Refactor it into the structured format: extract shared URL pattern, method, and headers into meta.
  3. Add validate: fields to check at least one response value per row.
  4. Import and compare — the tests should behave identically but with validation.

Exercise 3 — Export and Round-Trip

  1. Open any existing test in the Test Editor.
  2. Click Export Template → choose JSON format.
  3. Open the exported file in a text editor, add 2 more rows with different parameters.
  4. Re-import the modified file — verify the new rows appear as additional tests.
📋 Note JSON data files are fully compatible with the existing CSV/Excel import — you can mix formats within the same project. Use whichever format is most convenient for each data source.
